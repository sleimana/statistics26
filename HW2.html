A toy public-key scheme on secp256k1 against the Caesar cipher: encryption, statistical cryptanalysis and a search over a restricted key space. Student: your name, ID 0000000.

§1Toy elliptic-curve encryption (ECIES-like)

The scheme reuses the scalar multiplication of Homework 1 on the real curve secp256k1. The only "toy" element is that the private key is drawn from a small range [1, 2b−1].

Algorithm and role of the keys

  1. Key generation (receiver). Pick the private key d ∈ [1, 2b−1] and publish Q = dG. Only d stays secret.
  2. Encryption (sender, uses only Q). Pick a fresh ephemeral scalar r (full 256-bit range) and send C₁ = rG. The shared point is S = rQ = rdG.
  3. Derive a key stream from S: blocki = SHA-256("HW2" ‖ x(S) ‖ i). The ciphertext body is C₂ = M ⊕ stream.
  4. Decryption (receiver, uses d). S = dC₁ = drG, the same point, so the same stream gives M = C₂ ⊕ stream.

The public key lets anyone encrypt. The private key is the only way to rebuild S from C₁ (Diffie–Hellman). The ephemeral r makes encryption randomised: the same message encrypts differently every time.

§4Statistical cryptanalysis of Caesar

Reference model: letter (and letter-pair) frequencies of English estimated from a training corpus, which you can replace with your own. For each candidate shift s, decrypt and score how English-like the result is. The best score wins.

The scoring functions compared

  • χ² distance Σ (Oc − Ec)²/Ec between the observed letter counts of the candidate plaintext and the expected counts. Lower is better.
  • Unigram log-likelihood Σ log p(c). This is the maximum-likelihood choice of s under the model "letters are i.i.d. from English".
  • Bigram log-likelihood Σ log p(ct | ct−1), with add-one smoothing. It uses context, so it needs fewer letters.
  • Exhaustive search + dictionary: try all 26 keys and count the words that appear in a list of common English words. This is the "human" method, and it is reliable once a few words are present.

§5Effectiveness vs. ciphertext length

The test texts are random windows of a held-out passage, not the training corpus, with a random key each time. Statistics need enough letters: with 5–10 letters the frequency methods often fail, because short English fragments deviate strongly from the average distribution. From about 30–40 letters on, every method recovers the key almost always. The bigram model converges fastest, because letter pairs ("th", "he", "in") carry more information per letter than single frequencies. The dictionary method is the slowest at short lengths, because it needs whole common words to fall inside the window. Limitations: the attack assumes the plaintext language is known and the text is "typical". Lipograms, code, lists of numbers or a different language break the reference model. Exhaustive search always finds the key among 26 candidates; statistics are only needed to recognise it automatically.

§6Attacking the toy ECC through its restricted key space

The attacker knows only the public key Q, the ciphertext (C₁, C₂) and the fact that d < 2b. Two algorithms:

  • Exhaustive search: compute G, 2G, 3G, … by repeated addition until the point equals Q. That takes up to 2b additions (average 2b−1).
  • Baby-step giant-step (Shanks): write d = i·m + j with m = ⌈2b/2⌉. Store jG for all j, then walk Q − i(mG) until a match. That takes about 2·2b/2 operations and 2b/2 memory.

Statistical vs. key-space attack. The Caesar attack reads information from the ciphertext: its letter distribution is a noisy rotated copy of English, and more ciphertext gives a more reliable estimate. The ECC attack ignores the ciphertext statistics completely, which carry nothing. It exploits only the fact that the key generator was weak, and it succeeds with certainty once the search covers the key range, whatever the message length.

§7Why the same approach fails on properly configured ECC

With d uniform in [1, n−1] and n ≈ 1.16·1077, exhaustive search needs about 2255 additions on average. The generic algorithms (BSGS, Pollard rho and kangaroo) need about √n ≈ 2128 operations, and for secp256k1 no faster algorithm is known (ECDLP). The measured speed in §6 turns that into time: see the extrapolation printed under the chart. It exceeds the age of the universe by dozens of orders of magnitude, even with all computers on Earth working in parallel. The Caesar weakness, in contrast, does not depend on computing power at all: 26 keys and frequency leakage are structural.
